# Research defense artifacts

`./qcsd-lab fit <sealed-fitting-result>` creates one fixed, sealed runtime
bundle at `artifacts/research-1200/` containing exactly:

- `traffic-morphing.json`
- `wtf-pad.json`
- `walkie-talkie.json`
- `provenance.json`

Generated bundle contents are intentionally ignored by Git and excluded from
the Docker build context. The production research bundle has been fitted and
verified locally; its generated contents are deliberately not checked in.

Current fitting contract 5 binds Traffic Morphing schema 2, Walkie-Talkie
schema 5, and WTF-PAD schema 2. Walkie-Talkie uses the exact held
receiver-continuation contract generated by
`qcsd_lab.fitting_walkie_talkie 2.1.2`: preprovisioning to the configured chaff
limit before due outgoing actions, peer acknowledgement of the gap-free
request through FIN, deterministic acknowledged-candidate reservation before
base allocation, causal release after base signals, whole-cell allocation, and
an explicit prepared-prefix consumability precondition. Ordinary base receive
allocation prioritizes application streams, then peer-acknowledged nonreserved
controlled chaff, with exact capacity before bounded framing claims. Fitting
inputs do not observe the runtime preprovisioning, peer acknowledgement,
reservation lifecycle, or response prefix.
The receiver contract also requires the initial priority-aware,
largest-eligible chaff selector to yield a known-valid, dependency-free,
same-origin resource with at least one 1200-byte cell of effective length; the
runtime validates the endpoint-relative part after readiness.
The first moulded component must be outgoing-positive, and the configured
chaff-stream maximum must cover the maximum reserve horizon plus one. Required
nonblocking QPACK chaff request STREAM frames through FIN must fit within the
residual Normal-priority budget after due higher-priority application frames at
each positive outgoing horizon start. Fitting inputs do not expose the
HTTP/3/QPACK prefix sizes or transport budgets needed to prove that prepared
precondition. Before each incoming component's first base allocation,
acknowledged request survivors must cover its reserve horizon plus one. Loss
below that bound holds allocation; the contract promises neither targetless
retransmission nor generic post-loss liveness.
Schema-3 and schema-4 artifacts are superseded diagnostic candidates and are
rejected by current loading. Regeneration from the same sealed fitting result
changes receipts and hashes but not numeric moulds, pairing, or costs.
Preserved schema-2 evidence remains historical-only.
