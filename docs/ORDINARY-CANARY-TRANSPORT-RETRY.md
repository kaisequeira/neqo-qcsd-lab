# Ordinary canary transport retry

An explicit schema4 readiness reference retains the original ordinary capture,
plan, canonical runtime, full result graph, image/client and application policy.
It also retains the failed deep operation with returncode1. The successful retry
uses the original verifier program and image, the exact original renewal file,
and only the complete authenticated group roots added as read-only mounts. Its
operations live in a new namespace. This is zero-credit readiness evidence.

The study reader is a separately inventoried HOST overlay. All original Source
membership, capture, acceptance, traffic and Native bytes are exact; only the
four named readiness controls and the ordinary mount selector differ. Legacy
schema1/2/3 command checks remain unchanged. The original image is not rebuilt.
Formal image checks mount `CaptureSpec.module_root` read-only and load its reader
through the existing explicit study-overlay interface. The actual runtime
Source/client/image labels remain those of the original measured runtime.

Use `tools/rapid_ordinary_canary_retry.py runtime-overlay` to create a new runtime
spec changing only `module_root`, then `publish` to create the typed readiness
map. Existing `tools/rapid_undefended_capture.py inputs` and `plan` consume that
map and runtime. Their four control modules remain byte-exact. Preserve failed
deep logs and all original plan/setup/runtime files. A readiness retry grants no
capture or scientific credit.

The retry command retains the recipe/helper mounts from the original failed
operation. The prospective ordinary emitter mounts the recipe from the bound
clean runtime and authenticates its original plan hash. It never substitutes
the overlay emitter's own bytes for the original verifier.
