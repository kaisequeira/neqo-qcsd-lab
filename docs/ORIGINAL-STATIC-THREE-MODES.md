# Undefended, Tamaraw and CS-BuFLO on complete supplied graphs

These three settings use byte-identical copies of the original admitted static
workloads. Every resource, origin, dependency, header and original GET receipt
is retained. They do not need a FRONT or BuFLO policy amendment.

The separate prospective scheduling contract is implemented in
[rapid_original_static_parallel_schedule.py](../src/qcsd_lab/rapid_original_static_parallel_schedule.py).
It grants authority for one selected setting at a time. The target remains
50 classes × 5 settings × 64 visits = 16,000 formal traces.

## Before a setting starts

1. Retain the original enrollment and copy its complete admitted manifests
   unchanged into the new execution checkout.
2. Close a clean matching runtime with its actual installed client and Source.
3. Collect and verify the batch's current named 120-response qualification.
   No fitting or browser collection is required. An undefended diagnostic
   canary may precede qualification; the formal plan still binds the named set.
4. Run one complete site visit for the selected setting, then run installed deep
   verification and publish its ordinary readiness reference.
5. Publish a serial four-visit base plan with only that setting ready.
6. Use `original-static-scheduling` to declare the new scheduling capsule,
   then publish a parallel plan with that capsule. Both canonical arguments
   must identify the same current runtime.

The public CLI is [tools/rapid_rolling_capture.py](../tools/rapid_rolling_capture.py).
The existing parallel preparation, worker release, deep verification and
failed-lane recovery APIs apply. A failed lane gains no accepted samples; a
completed peer keeps its original evidence and exact settings.

## What remains separately bound

FRONT and BuFLO retain their existing amendment and scheduling contracts.
They cannot enter this three-mode capsule. Older lanes continue under their
original frozen Source, runtime and client; a later imported verifier cannot
silently reinterpret their control hashes. A mixed final corpus must reopen
each lane using its authenticated epoch and count each formal slot once.

This Source extension and HOST tests establish the prospective contracts.
Actual qualification, capture, deep verification and two-worker recovery
remain necessary before claiming live readiness or scientific progress.
