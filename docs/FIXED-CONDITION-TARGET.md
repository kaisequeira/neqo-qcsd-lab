# Prospective fixed conditions and slot progress

This separate target covers 50 admitted full resource graphs, five declared
conditions and 64 independent slots per class and condition: 16,000 traces.
Planning may start with the currently verified class prefix. Extending membership
appends indices and preserves existing graphs, caps, conditions and target ID.

Historical progress stays linked as audit history. It grants no target credit.
Initial progress can carry original ordinary or FRONT traces only when their
full condition, graph, seven capture limits, Native and client match exactly.
TAM8192 starts at zero. Later TAM8192 traces must belong to intents created after
the target declaration. The old SCI36 anchor is not this target's authority.

## Public controls

Use [the portable tool](../tools/rapid_fixed_condition_target.py) with Python
`-I -B`. Every input flag has a required SHA256 companion. Outputs and original
proof audit directories are create-only and separate from measurement evidence.
Normal clones contain every tool and reader used by these controls.

- `condition` authenticates frozen campaign configuration and complete Native
  configuration values. The referenced Native JSON can be a prospective value
  declaration; this action grants no eligibility or trace credit. Parameter
  locations may move only while their full hashes/provenance remain exact.
- `target` reads a hash-bound JSON request with `namespace`, `enrollment`,
  `conditions` (all five mode-to-condition references), `native_head`,
  `client_sha256`, and `history`. An extension adds `parent`.
- `audit-complete` binds an actual installed measurement release through the
  trusted dynamic Source reader and invokes the unchanged original epoch deep
  program on the requested complete lane closures. It has no SCI anchor.
- `audit-partial` runs a separate independent original deep verification of a
  typed dynamic incomplete-lane receipt. Both original operations remain bound.
  Failed/planned rows and the incomplete aggregate are never promoted.
- `initialize-progress` or `append-progress` consumes these audits. A logical
  slot and an original physical sample can each appear only once.
- `chunk-inputs` publishes a planning-only snapshot of exact class rows,
  homogeneous caps and remaining vectors. `check` reports numeric progress.
- `publish-final` requires exactly 50 × 5 × 64 authentic accepted slots and
  closes every original raw file, mode and directory membership dependency.

Full resource IDs, URLs, request headers, repeated resources, origins,
dependencies and expected statuses are retained through original proofs and
graph fingerprints. Per-class recording/response budgets cannot be changed by
a target or progress update. Condition hashes bind the full Native configuration
and application/body/primary/capture acceptance policies. A named qualification
set's location is not a traffic setting; its original deep authority remains
mandatory. TAM8192 requires fresh matching qualification and canary evidence.

## Consumer ABI and current limits

`remaining_vectors(progress)` returns all 0..63 slot vectors per registered
class and mode. `chunk_inputs(progress, classes, mode, maximum=16)` returns
target/progress references, target ID, exact condition, full immutable class
rows, caps and contiguous ranges. A cohort needs identical vectors and caps;
split recovery groups remain separate. `read_chunk_inputs` authenticates the
published planning snapshot. `input_files`, `directory_dependencies` and
`roots` expose exact authenticated transport inputs and membership selectors.
Consumers must preserve these file/tree/shallow-directory distinctions.

This role does not widen old chunk policies or old capsules. Target-aware
serial/chunk/capsule dispatch must explicitly bind these inputs to current
qualification, canary, runtime and lane authority before capture. The supplied
dynamic partial reader covers serial host-returncode-1 lanes without interruption
in the original four-visit or explicit 1–16 chunk layout. Parallel worker partial
intake additionally needs its actual actuator/retirement and operator/batch
closures; a serial partial receipt cannot substitute for those joins.

Source and HOST controls are engineering evidence. They do not prove installed
TAM8192 readiness, simultaneous workers, recovery or final corpus coverage.
