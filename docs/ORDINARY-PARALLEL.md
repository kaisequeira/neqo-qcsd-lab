# Current ordinary parallel workers

This is a prospective HOST control extension. It has no installed runtime,
physical capture, deep packet proof or formal credit of its own.

The distinct scheduling capsule wraps an unchanged serial ordinary plan. That
base can contain legacy four-visit lanes or authenticated remaining-slot
ChunkLane workers with 1–16 visits. The original full ordered resource graphs,
requests, all seven limits, current image/client, body policy and traffic
parameter hashes remain fixed. Two workers must occupy disjoint logical slots.
Existing defended and ordinary serial defaults keep their original validators.

## Current group readiness

A new schema5 reference, qcsd-current-ordinary-successful-group-canary-v1,
authenticates the normal successful capture and deep operations from a matching
current runtime. Deep verification transports the renewal leaf and every
authenticated group preparation root read only. It retains the original
packet/deep acceptance body.

Schema4 historical failed-deep transport retry is a separate contract. It
cannot supply this new capsule. Source equality is checked against the current
complete canary/runtime inventory; no earlier canary or Source equivalence is
claimed for these new controls. Root must install this Source using the original
verified Native client and obtain its own ordinary current canary/readiness.
No padding response qualification, fitting or Native compilation is required.

## Root sequence

After the actual matching runtime, current ordinary renewal, normal group
canary/readiness and serial ordinary input/plan exist:

1. Retain the actual44-slot anchor and its original eight individual proofs.
   A fresh current join may consume those unchanged original proofs without
   repeating their deep verification. The actual SCI9 class1 TAM slots are
   0–3 and12–31; the other eight retained TAM slots belong to classes2 and5,
   visits4–7. Synthetic test progress is never a credit source.
2. Use the existing public chunk-policy and chunk-plan commands for the serial
   base. Set --mode undefended and --maximum-visits 16. Supply a genuine
   authenticated prior-progress reference; gap/tail chunks remain bounded.
3. Publish ordinary-scheduling with --spec, --runtime-spec,
   --qualification-spec, --original-canonical, --current-canonical, --output
   and --reason. Both canonical flags name the same actual current canonical.
4. Publish ordinary-parallel-plan with --spec, --scheduling, --output and
   --spec-output, each output in a fresh create-only study namespace.
5. tools/rapid_formal_parallel.py --spec SPEC --evidence-root ROOT --lane FIRST
   --lane SECOND --output AUTHORITY prepares two exact worker claims.
   tools/rapid_parallel_capture.py launch --authority AUTHORITY --output OUTPUT
   owns their actual gated actuation. Its verify action independently reopens
   each worker and the terminal batch.
6. A terminal failed worker does not erase or invalidate its successful peer.
   The existing failed-only successor keeps the logical slot vector and
   immutable earlier attempt, then publishes a fresh matching capsule/wrapper.
   Good peer completion remains independently creditable after original deep
   verification. Partial traces within a failed parallel worker still need a
   distinct authenticated actuator/retirement/batch/deep reader; the serial
   partial-reader contract cannot be substituted.

The release fence observes complete raw-input bytes, full file and directory
modes, membership, original canonical recipes, current source copies and sealed
canary evidence before worker birth. It excludes mutable result/output parents.
The serial launcher defaults QCSD_PARALLEL_HOST_PYTHON to its actual calling
sys.executable when no explicit override exists.
