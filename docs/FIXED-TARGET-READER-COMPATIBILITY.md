# Fixed target reader compatibility

Retained target, progress, and audit references keep their original paths, hashes, full file modes, Source labels, and original operation identities. The reader authenticates both producer and current files.

Membership allows a rolling module change only when its entire AST remains identical outside three planning bodies: `_sites_from_enrollment`, `publish_plan`, and `verify_capture_plan`. Their eager decorators, annotations, and defaults remain protected; only the two explicit optional subgroup parameters may be absent. Enrollment and admission validators stay protected. Every original graph, raw file, complete tree, class index, cap, condition, Native/client identity, and logical slot remains checked.

Backward reader compatibility recognizes only the exact original compatibility guard shapes and identical residual scientific code. Original runtime registrations retain their original six reader refs, request Source root, proof program, and authenticated interpreter command/binary. Retained module-overlay registrations also keep their original four reader refs and separate installed-runtime identity. A matching reader can be relocated without claiming the old operation executed current code. Interpreter aliases and their resolved binary roots are transported explicitly.

This does not grant trace credit, repair changed original directory membership, or waive current executing/installed chunk controls. A current chunk planner needs its actual matching packaged Source and runtime. Historical failed intakes remain preserved. A stable Git registration may be rebound and the original complete audit rerun through existing public APIs, with no capture or qualification replay.
