# Fifteen-completion AEL prerequisite

The optional flight flag `--response-qualification-policy ael-equals-identity-three-by-five-stable-wire-response-v1` requests a fresh response-only prerequisite through the existing Native AEL command. It requires three independent connection epochs with five genuine passing requests each. The named sidecar is schema 1 and its capture manifest is schema 3. The default 120-completion identity prerequisite remains available without this flag.

The selected response must come from the unchanged complete prepared graph, share the primary HTTPS origin, and have an exact prepared wire body between 1,200 bytes and 1 MiB. Its existing AEL headers must equal the current identity padding projection exactly. Status, wire bytes, body SHA, packet evidence, request sizes, implementation and Native provenance are checked by the unchanged original reducer. A gzip response can qualify only when those checks pass; an old failed identity receipt has no new authority.

Setup, plan and completion retain the explicitly named prerequisite. A separate create-only `_ael-fifteen-prerequisite.json` binds the unchanged original named manifest, current producer bytes and modes, and fresh installed qualification Source. Only this authenticated record selects schema 1 in a fresh campaign. Materialization retains it in the sealed frozen inputs; the original schema-3 reader and Native identity checks remain active. An unmarked schema-1 sidecar cannot enter a fresh campaign; the marker cannot authorize schema 2 or budget evidence. Qualification evidence is fresh and create-only. Capture limits, the Native binary, graph resources and origins, the application body policy and fixed defence configuration remain authenticated by the original flight and capture readers. This prerequisite produces no scientific credit.
