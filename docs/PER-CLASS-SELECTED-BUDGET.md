# Add larger sites while retaining the first eleven classes

The per-class selected ledger keeps the existing eleven class identities and
their accepted historical trace slots. It can append complete sites admitted
under the prospective larger GET budget, including the retained q53 full GET.
The final target remains **50 classes × five modes × 64 visits = 16,000 traces**.

The original selected V1 input and enrollment validators remain unchanged.
New budget input receipts and a separate per-class policy make the new limits
explicit. Every request occurrence, dependency, safe header, query byte and
approved origin stays in its full original graph.

| Classes | Response limit per resource | Recording budget per visit | Request timeout |
| --- | ---: | ---: | ---: |
| Existing ordinary selected classes | 16 MiB | 64 MiB | 120 seconds |
| Prospectively admitted larger-budget classes | 64 MiB | 256 MiB | 120 seconds |

Each class retains the same limits across undefended, FRONT, Tamaraw, BuFLO and
CS-BuFLO. Group only classes with identical seven-field limits in one flight.
The selector rejects a mixed-budget flight before publishing its enrollment.
The existing four-visit lane layout is preserved.

## Public path

Use [the per-class tool](../tools/rapid_per_class_selected_capture.py):

1. `audit-budget` authenticates the original admitted budget terminal in its
   exact approved Core002 Source. Its complete inventory is pinned. Retain the
   actual command, status, stdout and stderr. This is one original-authority
   audit per new selected input, with no admission or trace credit.
2. `publish-input` and `prepare-input` independently reopen that site's own
   complete bootstrap/full GET. They preserve the original producer, discovery
   and measurement runtime labels. Capture readers retain the audit artifact
   and own raw GET; they do not re-run the unrelated acquisition prefix.
3. `init` creates a new policy bound to the existing eleven-class enrollment,
   accepted-slot progress manifest and actual matching new runtime.
4. `enroll` appends one to five genuinely admitted, distinct classes; class12
   follows class11. `verify-enrollment` checks the exact predecessor, order,
   full input/manifest bijection and homogeneous selected limits.
5. Use [the mode-flight tool](../tools/rapid_class_mode_flight.py) on the new
   enrollment. Undefended/Tamaraw/CS-BuFLO accept its explicit plain selected
   role. FRONT and BuFLO use a distinct per-class fixed-policy amendment over
   the same resources. BuFLO retains the fixed200s policy.

Each mode still needs its own authenticated current inputs, complete-graph
canary, independent deep verification and readiness. Response-only
qualification reuse requires the existing explicit compatible producer and
consumer contract; a changed Source never automatically promotes old evidence.
This feature changes no Native bytes and requires no fitting or global CDP/110
qualification gate.

## What is preserved and what remains prospective

The old eleven enrollment rows are carried without changing their fields;
per-class limits are added from their original policy. Existing accepted slots
retain their actual original Source/runtime/capture/deep receipts. The new
policy binds the historical progress manifest and grants no credit itself.
Final aggregation must reconcile independently verified unique
class/mode/visit slots across the linked epochs; the ledger does not relabel or
automatically re-credit old traces.

This version supports serial capture. The released selected-parallel V1 capsule
continues to accept only its original 16/64 selected V1 contract. A distinct
per-class capsule is required for parallel budget classes. A new current
installation and real canary are still needed before claiming this authoring
Source can capture q53. HOST fixtures verify the real retained q53 GET and
eleven seed identities; their new runtime/publication boundaries are fixtures.

Reject malformed/unknown roles, changed producer or validator Source, incomplete
GETs, trimmed graphs, changed policies/profiles/caps, class duplication,
unassessed admissions and mixed limits. The original Core Source directory is
required when creating the audit; installed artifact-only readers authenticate
the pinned inventory and current validator bytes without mounting that old
author checkout.
