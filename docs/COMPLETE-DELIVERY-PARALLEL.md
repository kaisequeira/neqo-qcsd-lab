# Prospective parallel complete delivery

Original-static and amended-static scheduling retain their existing artifact
types and worker/launcher ABI. Their schema-one contracts retain strict body
comparisons. A serial base plan with the explicit
`complete-current-application-delivery-v1` policy publishes a schema-two
capsule under its distinct complete-delivery contract.

The capsule binds the unchanged full graphs, exact current runtime/client,
control and policy modules, one setting's full named120 qualification and
current complete-policy canary/deep/readiness. The new plan must retain the
exact same policy and optional qualification witness. Unknown/null/Boolean
tags, old capsule versions, another witness or changed raw evidence refuse.

Use repository-relative commands from a matching installed clean Source:

```sh
python3 -B tools/rapid_rolling_capture.py original-static-scheduling \
  --spec "$task_serial_spec" --runtime-spec "$task_runtime_spec" \
  --qualification-spec "$task_qualification_spec" \
  --original-canonical "$task_current_canonical" \
  --current-canonical "$task_current_canonical" \
  --output "$task_fresh_capsule" --reason "$task_declared_parallel_scope"
```

Undefended, Tamaraw and CS-BuFLO use the original-static action. FRONT and
BuFLO use `static-scheduling` with their actual current amendment. Original
settings may carry the explicit qualification-only witness from their serial
base plan; the original sidecar labels stay original. Amended settings require
fresh post-declaration qualification and refuse original-group witness reuse.
All schema-two settings use the existing prepared-response-budget schema-three
named sidecars. This does not relax chaff identity or terminal rules.

Public `plan` uses the same `--application-body-identity-policy` and optional
`--qualification-delivery-compatibility` flags as the serial flight, plus the
fresh `--scheduling` capsule. Select two virgin registered four-visit lanes
with the ordinary parallel tool. Each worker has its own result namespace and
terminal evidence. A failed lane alone may use its immediate generation-two
successor; a completed peer is immutable and cannot be recaptured as recovery.

Selected-ledger scheduling remains a separate prospective authority. This
package does not widen its existing serial-only contract, fit resources,
change traffic/caps/Native, bridge old measurement Source, or claim actual
concurrent capture. HOST fixtures substitute runtime, named120, canary and
actuation boundaries explicitly. Root owns the later physical two-worker and
single-worker recovery demonstration.
