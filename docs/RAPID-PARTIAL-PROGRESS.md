# Partial progress and remaining slots

`rapid_partial_progress` joins an existing genuine scientific progress manifest
with independently verified individual accepted traces from a terminal incomplete
original V17 lane. It preserves the failed aggregate, failed attempts, original
graphs, class identities, Source/runtime/client labels and zero aggregate lane
credit. Its individual rows can be used by remaining-slot planning and the
separate cross-epoch corpus reader.

The first supported producer is the unchanged original partial reader/CLI and
the exact registered 86cd/c24 paired Git release. The inventory is authenticated
by the unchanged original full Source validator once within its owning action.
Both public `declare` and subsequent public `verify`
must have real successful recorder start/completion/stdout/stderr records. Their
two separate original deep operations must match the unchanged original program,
reader, interpreter, inputs, chronology, full accepted subset and raw dependencies.
Collector status alone supplies no authority.

## Public Python API

```python
from qcsd_lab import rapid_partial_progress as partial

reference = partial.publish(
    prior_progress=original_progress_reference,
    enrollment=current_enrollment_reference,
    partials=[{
        "receipt": original_partial_receipt_reference,
        "tool": original_partial_public_tool_reference,
        "declare": actual_declare_operation,
        "verify": actual_independent_verify_operation,
        # Required only when both public operations ran in the original image:
        "offline_image": {
            "artifact_type": partial.OFFLINE_TYPE,
            "runtime": original_canonical_runtime_reference,
            "root_inputs": original_proof_input_authority_reference,
        },
    }],
    output=fresh_output_path,
)
payload, files = partial.read_inputs(reference)
```

References retain absolute paths, SHA256 and permission mode. Operation mappings
have exactly `started`, `completed`, `stdout`, `stderr` references. The output is
create-only. `validate`, `accepted_slots` and `input_files` also remain public;
`read_inputs` obtains payload and transport files with one semantic derivation.
Consumers authenticate existing recorded proof; they do not run the old deep
verifier again. Original Source files, both inner and outer raw operations,
reader, graph and prior progress inputs are retained in `files`. The HOST branch
retains its interpreter file. In the explicit offline-image branch the interpreter
is an original immutable-image label; it is never presented as a HOST file.
This branch authenticates the original image/client/Source export and input plan,
network-none/read-only sandbox, one workspace RO mount and one owned proof RW
mount, exact public CLI flags and separate inner proof records. Workspace and
proof paths derive from authenticated inputs, with no fixed workstation prefix
or universal Root-driver pin.

An owning consumer may call `observed_inputs(files)` after `read_inputs` to export
already authenticated byte/mode references without reading large artifacts again.
Call `close_operation(context)` before publication/effects and success: it freshly
checks file bytes/modes and the original exact **shallow** directory memberships.
No recursive raw directory watch or per-row deep replay is used. Original Source
membership and paired Git metadata are also fenced. Snapshots are operation-local
and acquire no independent scientific authority.

Individual rows retain all seven original `configuration.limits` fields, including
capture180s, request120s and original max_attempts3. Current selected scheduling
may declare max_attempts1; six other declared limits must remain compatible. The
original measured attempt count is preserved rather than rewritten.

`rapid_slot_chunks.prior_progress` accepts this distinct artifact explicitly.
Old complete-lane progress remains on its existing strict branch. Duplicate
logical slots or physical samples, substituted Source or graph, absent/failed
independent verification and altered raw bytes/modes/membership are refused.
Only proved good slots are omitted from future plans; failed or planned samples
remain eligible for a prospective new attempt.
