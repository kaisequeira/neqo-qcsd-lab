# Fixed conditions with prospective Native epochs

The dataset remains exactly **50 distinct sites × five conditions × 64 logical
slots = 16,000 accepted traces**. The additive
[epoch reader](../src/qcsd_lab/rapid_per_mode_native_target.py) joins original
[fixed-target](../src/qcsd_lab/rapid_fixed_condition_target.py) declarations and
progress. It changes no admission, full graph, capture cap, traffic parameter,
qualification, practice, or original deep acceptance rule.

## Preserve original credit

Each mode has an explicit finite ordered list of Native/client epochs. The
current intended initial lists are ordinary, FRONT and BuFLO with their original
c24 client; TAM8192 with original c24 followed by the repaired Native/client;
and canonical CTSP CS-BuFLO with the repaired pair only. Original valid TAM4
remain scientific credit with their original measurement labels. Historical
TAM16 recordings do not acquire TAM8192 credit. Original CS rows are retained
as history and cannot enter the repaired CS numerator.

Every selected row is authenticated by the unchanged original v1 target,
progress and original installed/deep proof readers. The reducer copies rows
verbatim. All five condition identities and hashes, including empty modes, must
match the retained original target. A selected v1 progress target must be the
declared target or an authenticated descendant with the same target identity.
A logical `(class, mode, slot)` or physical `(result, sample)` can occur
only once across the complete joined dataset, including across Native epochs.
The mandatory original progress anchor prevents dropping unaffected recordings.
No HOST fixture, declaration, runtime installation or diagnostic grants credit.

## Declare before repaired captures

Publish and install the actual clean repaired Native/Lab release first. Bind its
actual runtime through the existing installed Source reader or explicit module
overlay reader. Then declare an original v1 target for that truthful Native head
and binary SHA, using the unchanged five full condition descriptors and original
class membership. The new epoch target request contains `namespace`,
`carry_progress`, and `mode_targets`; each mode maps to an ordered list of
`{"target": ORIGINAL_V1_TARGET_REF, "source_binding": REF_OR_NULL}`. Only the
first original c24 epoch has a null binding. Every repaired epoch requires an
authenticated clean installed Source/runtime proof before its declaration.

The [public tool](../tools/rapid_per_mode_native_target.py) offers `target`,
`initialize-progress`, `append-progress`, `check`, `chunk-inputs` and
`publish-final`. All public input files require their exact SHA flags. The
`mode_progress` input is a JSON object mapping each mode to the same-length
ordered list of original v1 progress references. New original proofs are first
audited and appended by the existing v1 public reader, then joined here.
Repaired intents preceding their own epoch declaration are refused.

An explicit later target revision may append finite epochs, preserving every
old ordered prefix, Source binding, timestamp, class and accepted row. Initialize
that revision with `--previous-progress` bound to its immediate predecessor.
It cannot reset an affected mode, remove old valid credit or interrupt another
mode. Existing targets and progress remain immutable and separately readable.

## Plan from the joined gaps

`chunk-inputs` requires an explicit `--epoch-index`. Its remaining slots combine
all valid epochs of the selected mode: repaired TAM must skip original TAM0–3.
The output has a distinct planning-only type. Existing v1 target chunks and
parallel capsules do not automatically accept it. A future explicit consumer
must bind that type, current full graphs, caps, runtime, qualified group and
canary; using the repaired v1 target's empty TAM vector would duplicate credit.

Final publication requires 50 original class identities, five unchanged fixed
conditions, all 64 slots per class/mode, no duplicates or holes, and the retained
original Source/raw dependencies. Existing c24 measurements and runtime are
never relabelled to the repaired binary. The new release/client has no capture
credit until real condition-specific canary, formal capture and independent
deep proof operations succeed.
