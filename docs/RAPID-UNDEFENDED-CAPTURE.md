# Ordinary formal capture from admitted full graphs

The explicit `qcsd-rapid-admitted-ordinary-only-input-v1` contract permits serial
ordinary capture after that setting's own full-site canary and independent deep
readiness proof. It requires no padding-response qualification, fitting or
readiness for another defense. Workload/preparation files, request headers,
resource occurrences, dependencies and admitted response/recording caps remain
unchanged. The qualified five-setting default remains unchanged.

## Root steps after matching Source/runtime installation

1. Reissue the selected validation receipts for the exact enrolled tail when
   its old direct Source differs. This uses the existing
   `rapid_selected_capture_input.publish_input` / `prepare_input` APIs on the
   same retained raw GET, with `selected_capture_amendment._original` retaining
   original audited class/graph/provenance labels. It performs no network GET:

   ```sh
   python3 -I -B tools/rapid_undefended_capture.py renew \
     --enrollment /absolute/enrollment.json \
     --output /absolute/fresh/ordinary-renewal.json
   ```

   The current eleven-class enrollment's old preparations remain unchanged.
   New selected receipts and manifests explicitly retain original GET producer,
   audit, requests, graph, response evidence and budgets.
2. Use the published portable class flight tool to stage and finalize the exact
   enrolled tail (one to five classes), with `--mode undefended`, the current
   immutable canonical runtime, `--ordinary-renewal` pointing to this receipt,
   and a fresh flight namespace.
3. Run its installed preamble and ordinary preflight, full-site canary,
   independent deep check and readiness publication. Skip `qualify-image`.
   No qualification witness is needed for ordinary responses. Preserve the
   selected application body policy through the canary and formal plan.
   The finalized command file has no qualification action. The portable
   `run --step preflight` requires the actual successful preamble;
   `run --step inputs` and `run --step plan` use the typed ordinary tool below.
   The plan action requires the separately recorded successful input action
   and the setting's actual readiness map.
4. Publish a new ordinary input with the matching flight's public runtime spec:

   ```sh
   python3 -I -B tools/rapid_undefended_capture.py inputs \
     --enrollment /absolute/enrollment.json \
     --runtime-spec /absolute/flight/runtime-spec.json \
     --ordinary-renewal /absolute/fresh/ordinary-renewal.json \
     --output /absolute/fresh/ordinary-input.json
   ```

5. Publish the formal plan using the actual ordinary readiness reference:

   ```sh
   python3 -I -B tools/rapid_undefended_capture.py plan \
     --enrollment /absolute/enrollment.json \
     --runtime-spec /absolute/flight/runtime-spec.json \
     --ordinary-input /absolute/fresh/ordinary-input.json \
     --ordinary-readiness /absolute/flight/readiness.json \
     --output /absolute/fresh/plan.json \
     --spec-output /absolute/fresh/capture-spec.json
   ```

   For the declared complete-delivery policy add
   `--application-body-identity-policy complete-current-application-delivery-v1`
   and require the same tag on the actual canary. No witness or old qualified
   group is substituted into this ordinary contract.
6. Use the existing public `tools/rapid_rolling_capture.py launch`,
   `complete-lane` and `verify-lane` actions with this capture spec. Each lane
   covers four visits for the selected classes; sixteen blocks cover their
   ordinary slots 0..63. Select only genuinely missing slots according to the
   accepted progress authority; publication is not trace credit.

The new contract rejects defended modes, amendments, parallel capsules,
qualification witnesses and another enrollment/runtime/cap/Source. Its initial
scope is serial four-visit lanes. Partial recovery/chunk protocols remain
separate. Final corpus publication still requires fifty distinct classes,
all five settings and 64 complete, unique visits per class and setting (16,000).

Private HOST checks do not establish an installed runtime, canary or capture.
